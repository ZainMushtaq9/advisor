# Phase 3 — Database Architecture

Date: 2026-11-04. Status: implemented and tested on PostgreSQL 16.15
(local, this VM). No PSX data collected in Phase 3.

`DATABASE_RELATIONSHIPS.md` + `DATABASE_INDEXING_STRATEGY.md`, adapted

## Stack (unchanged, PKR 0)

PostgreSQL 16.15 (self-hosted) + SQLAlchemy 2.1.8 + Alembic 1.20.1 +
psycopg 3.3.7. No hosted database, no paid service, no new
dependency. pyarrow is NOT installed on this VM, so Parquet writing
is guard-raised, not faked (see `storage_engine.md`).

## Principles (enforced, not aspirational)

1. Provenance first: source, source timestamp, collected-at time,
   quality status on every market/financial/news/analysis record
   where meaningful, else via the parent row (see
   provenance_and_quality.md § Provenance scope, audit M7).
2. PKT for market meaning, tz-aware storage always.
3. Raw data and market history are immutable; corrections are new
   rows (triggers enforce this — see `integrity_rules.md`).
4. Gaps, not guesses: missing is absent or MISSING, never zero.
5. Conflicts side-by-side: grain includes source, so two sources
   disagreeing is two rows, never a silent merge.
6. Versioning, not overwriting: restatements are new versions with
   `supersedes_id`; only the `is_current` pointer may change on
   versioned tables (trigger-enforced).
7. Uncertainty is data: forecasts carry intervals and scenarios, not
   point estimates alone.
8. Paper portfolios only: no brokerage identifiers, no order path,
   no real trades, anywhere in the schema.

## What Phase 3 deliberately does NOT do

No PSX dataset collection, no KSE-100 backfill, no live collectors,
no frontend data pages (frontend is unchanged from Phase 2
foundation shells), no Docker/Playwright verification (both remain
UNVERIFIED from Phase 2), no auth design (no credential columns
exist anywhere in the schema).
